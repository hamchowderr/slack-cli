# AGENTS.md — slack-cli

Guidance for AI agents (and humans) working on this repo. Global conventions
live in the user's machine at `~/.claude/CLAUDE.md`; this file only covers
slack-cli-specific workflow.

## Finding work

This repo uses **beads** for issue tracking.

```bash
bd ready              # what's unblocked and ready to claim
bd list --status open # everything still open
bd show <id>          # details on one issue
```

If `bd ready` is empty, ask the human before inventing work. Don't create
issues for tasks the human didn't request.

## Workflow per feature

1. `bd update <id> --claim` to take the issue.
2. **Mirror to your in-session todo list immediately.** This is the three-way
   mirror (beads ↔ in-session todo ↔ TaskNotes) — the human watches the
   in-session list to confirm you're working on the claimed issue.
3. Implement on a feature branch (`feature/<slug>`). Never push to `main`.
4. Run `npm run typecheck && npm run build && npm run test` before committing.
   If any of those fail, fix before committing — don't skip the gate.
5. Commit message must reference the bd ID (`Closes slack-cli-<hash>.`).
6. Push the branch and `gh pr create`. **Do NOT merge** — PRs are reviewed
   and merged by the human.
7. After the human merges, `bd close <id> --reason "..."` and mirror the
   close to the in-session todo list. If the work shipped in a single PR,
   it's fine to close immediately on push too (with the PR URL in the
   reason).

## Commit convention

Use a HEREDOC to preserve newlines:

```bash
git commit -m "$(cat <<'EOF'
<imperative subject — one line, ends with (slack-cli-<id>)>

<paragraph of why and what>

Closes slack-cli-<id>.

Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
EOF
)"
```

## Architecture quick reference

- `src/cli.ts` — Commander entry point with every subcommand
- `src/client.ts` — `fetch` wrapper, types, `loadUsers` / `loadChannels` /
  `loadConnectUsers` / `resolveTarget` helpers
- `src/format.ts` — pure rendering (`renderMessages`, `formatReactions`,
  `formatFile`, etc.)
- `src/dates.ts` — date parsing helpers (`parseSlackDate`)
- `src/config.ts` — token resolution (`--token` → env → Infisical)
- `src/__tests__/` — vitest unit tests for pure functions only (no network)
- `dist/` — tsup output (gitignored); regenerated by `npm run build`

When adding a new command:
- Add the command handler in `cli.ts` (keep handlers slim — call into
  helpers in `client.ts` / `format.ts`).
- Add types to `client.ts` near the existing `SlackUser` / `SlackChannel`
  / `SlackMessage` interfaces.
- Mutation commands (send, update, delete, react) gate behind `--yes` to
  match the existing `slk send` pattern.

## Hard rules

- Never push to `main`. Always work on a feature branch.
- Never merge a PR. The human reviews and merges.
- Never amend a pushed commit or `git push --force`.
- Never call out to an external LLM (no `claude -p`, no Anthropic API).
  This is pure code work.
- Never commit `.env` files or hardcoded tokens. The `.gitignore` covers
  `.env*` but double-check before staging.
